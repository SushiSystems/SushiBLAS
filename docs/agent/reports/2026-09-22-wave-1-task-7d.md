## Found that the plan did not predict

- **`cli/pyproject.toml` defines no `test` extra.** The plan's step 3 for tasks 7a–7f installs
  `-e "./cli"` and runs `pytest cli/tests` directly, implying `pytest` is either already on the
  interpreter or pulled in transitively. Neither is true for a genuinely clean environment here;
  `pytest` had to be installed by hand. This does not indicate a defect in `cli/pyproject.toml` —
  a bare install-and-test check does not need a packaged `test` extra — but it is worth recording
  since the plan phrased step 3 as if the bare install would be enough to run the suite.
- **This repository has no `docs/reference/CHANGELOG.md` and did not fit the pattern the other
  five consumers use.** `sushiruntime`, `sushiengine`, `sushiai`, `sushidsp` and `sushitrack` all
  already carry `docs/reference/CHANGELOG.md` in the `# Changelog` / `## Unreleased` / entries
  shape that this task's instructions describe as "the format the other Sushi repositories use".
  `sushiblas` instead carries `docs/CHANGELOG.md` (no `reference/` folder), in a different,
  richer Keep-a-Changelog-style format with prose and section headings, referenced from its own
  `CONTRIBUTING.md`. Task instructions named `docs/reference/CHANGELOG.md` explicitly as a file
  this task may write, so that file was created, matching `sushiruntime`'s three-line header
  (`# Changelog`, blank, `## Unreleased`) followed by the one required entry line. This leaves
  `sushiblas` with two changelogs after this task — `docs/CHANGELOG.md` (pre-existing, unrelated
  to this task, untouched) and the new `docs/reference/CHANGELOG.md`. Whether `sushiblas` should
  be reconciled onto the shared `docs/reference/CHANGELOG.md` layout, or whether this task should
  instead have targeted `docs/CHANGELOG.md`, is a repository-layout decision outside this task's
  scope and file list; flagging it for the orchestrator rather than deciding it here.
